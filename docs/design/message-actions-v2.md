# 消息操作体验规范 v2

本规范以仓库内的设计令牌、组件代码和下述可验证尺寸为视觉基线，不依赖外部或
模型生成的概念图片。

## 产品语义

- 常用动作只在消息悬停、键盘聚焦或触屏环境中显示，避免长期占用正文空间。
- `重试` 不覆盖原回答：从对应用户消息之前创建非破坏性重试分支，再发送相同问题。
- `编辑并重新发送` 不篡改历史：从被编辑用户消息之前创建编辑分支，再发送新内容。
- `从此处开启新对话` 复制截至所选消息的上下文，原会话保持不变。
- `删除此消息` 删除所选消息及其后续消息；执行前自动创建快照。文件写入、命令和外部
  副作用不会因删除聊天记录而回滚，确认界面必须明确提示。
- 反馈只允许 `有帮助` / `无帮助` / 未选择三态切换，并持久化到消息记录。
- 重试分支按原始回答归组，提供上一版本/下一版本导航；每个版本仍是独立可恢复会话。

## 可见文案

- 常用动作：`复制`、`重试`、`有帮助`、`无帮助`、`更多`
- 用户消息：`编辑并重新发送`
- 更多菜单：`从此处开启新对话`、`复制为 Markdown`、`删除此消息`
- 删除确认标题：`删除这条消息？`
- 删除确认正文：`此消息及其后的内容将被移除，此操作无法撤销。`
- 副作用补充：`已写入的文件、已执行的命令或其他外部操作不会回滚。`
- 按钮：`取消`、`删除`

## 视觉系统

- 背景与容器继续使用现有 `--bg`、`--surface`、`--surface-raised`，不增加新的暖色或
  渐变。
- 主强调色继续使用 `--accent`；危险操作只使用 `--danger`。
- 消息操作按钮高度 28px，图标 13–14px，Lucide 1.5px 线性风格，正文标签 10px。
- 操作栏是开放式横向工具条，不把整条消息包成新卡片；按钮之间用现有边框分隔。
- 菜单宽度 210–228px，使用 `--bg-elevated`、1px 边框、现有小圆角和轻阴影。
- 版本导航位于操作栏末端，显示 `当前 / 总数`，左右箭头必须有独立可访问名称。
- 删除确认在桌面端靠近右下操作区域，移动端居中并占用安全边距。

## 交互与可访问性

- 消息容器 `:hover`、`:focus-within` 展示操作栏；触屏和 720px 以下始终显示。
- 更多菜单使用 `role="menu"`，菜单项使用 `role="menuitem"`；Escape、点击外部和选择
  操作均关闭。
- 删除确认使用 `role="alertdialog"`、`aria-modal="true"`，打开后聚焦取消按钮，
  Escape 关闭，确认期间禁用重复提交。
- 编辑态使用原消息宽度的多行输入框；`Ctrl/Cmd+Enter` 提交，Escape 取消。
- 正在流式生成时禁用删除、重试、编辑和分支；停止按钮仍由 Composer 提供。
- 复制成功、分支创建、删除/重试失败均通过 Toast 反馈。

## 响应式

- 960px：操作栏可换行一次，版本导航保持为一组。
- 720px 以下：只显示图标，文字通过 `aria-label` 与 tooltip 提供。
- 520px 以下：菜单限制在视口内，确认面板左右各保留 12px，操作栏允许横向滚动但页面
  不产生横向溢出。
